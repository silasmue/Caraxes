# ABI baseline

Scope: the recorded GSP ABI snapshot of 615.71.09 under `caraxes/abi/`, the tool that makes and diffs it, the 610-to-615 delta, and the workflow and drift check for the next driver.

## Facts

### The snapshot `caraxes/abi/gsp-615.71.09/`

- D20: 615.71.09 is the recorded GSP ABI baseline, and later drivers are handled as diffed deltas against `caraxes/abi/` [docs/vfio/README.md §Decisions D20].
- The MANIFEST records driver 615.71.09, the sha256 of `version.mk`, the repository commit (76e4440, "with uncommitted changes under crates/ or caraxes/tools/"), the generator command, the compilers (GCC 16.2.1, clang 22.1.8) and rows plus sha256 per file [caraxes/abi/gsp-615.71.09/MANIFEST].
- Every file is a sorted TSV with an SPDX header, so `git diff` of two snapshots is readable [docs/vfio/gsp-abi-615.md §1].

| File | One row per | Rows | Evidence |
|---|---|---:|---|
| `controls.tsv` | exported control id: params struct, size, layout hash, route, privilege, category A-E, device answer | 1397 | [caraxes/abi/gsp-615.71.09/MANIFEST; docs/vfio/gsp-abi-615.md §1] |
| `rpc.tsv` | RPC function: newest payload struct, size, hash, versions, sent by a GSP client, device | 232 | same |
| `events.tsv` | RPC event: payload, size, hash, dispatched by the CPU side, sent by the device | 45 | same |
| `classes.tsv` | `RS_ENTRY` class: route, reaches GSP, alloc params, in TU106's database, device | 224 | same |
| `boot.tsv` | `NV_ABI_STABLE` type or boot/transport struct the device implements: size, hash, version constants, stable flag | 41 | same |
| `layouts.tsv` | field of a laid-out struct: offset, size, origin | 666 | same |
| `constants.tsv` | derived transport constant, version constant, GMCAPI key | 242 | same |
| `enums.tsv` | enumerator of an `NV_ABI_STABLE` enum | 58 | same |
| `bitfields.tsv` | DRF bit range of a control or GMCAPI header | 924 | same |

- Of the 41 boot and transport types, 17 carry `NV_ABI_STABLE` (12 structs, 5 enums); what that tag covers: see [gsp-transport.md](gsp-transport.md) [caraxes/abi/gsp-615.71.09/boot.tsv; docs/vfio/gsp-abi-615.md §4].
- In the snapshot 844 controls route to GSP, of which 777 are answered (host-forwarded 69, synthesized 80, guest-derived 75, echo 65, refused 488) and 67 unhandled [caraxes/abi/gsp-615.71.09/controls.tsv; docs/vfio/README.md §Status 2026-09-25].
- Every size is compiler `sizeof`; the layout hash covers clang's record layout with every offset, type and field name, so a field moved at equal size changes it [docs/vfio/gsp-abi-615.md §1].
- The driver-side columns depend only on the tree (a second snapshot of the same tree is byte-identical); the device columns are read from the crate at the snapshot's commit [docs/vfio/gsp-abi-615.md §1].
- The "sent by a GSP client" column is a hand-kept survey (`GSP_CLIENT_SENDS_615` in `gsp-surface.py`), the one column that is not measured [docs/vfio/gsp-abi-615.md §4].
- The human-readable form is `docs/vfio/gsp-abi-615-tables.md`, generated by `render` [docs/vfio/gsp-abi-615.md §1].

### The tool `caraxes/tools/gsp-abi.py`

| Subcommand | Arguments | Does | Evidence |
|---|---|---|---|
| `snapshot` | `--ogkm DIR --out DIR [--tables FILE]` | writes MANIFEST and the nine TSVs of a tree, optionally the tables | [caraxes/tools/gsp-abi.py:1295-1298] |
| `diff` | `BASE NEW [--strict] [--out FILE]` | delta report of two snapshots or trees (a tree is snapshotted to a temporary directory) | [caraxes/tools/gsp-abi.py:1299-1304] |
| `render` | `SNAPSHOT [--out FILE] [--check FILE]` | markdown tables; `--check` exits 1 if FILE differs | [caraxes/tools/gsp-abi.py:1305-1308] |

- `diff` exits 1 when a struct the device implements changed size or field offsets, and with `--strict` on any driver-side difference; device-side changes are listed apart and never fail [caraxes/tools/gsp-abi.py:1166-1167; docs/vfio/gsp-abi-615.md §1].
- The inventory comes from `gsp-surface.py`, field offsets from `gsp-abi-sizes.sh` (boot structs) and `ctrl-layouts.py` (control structs the device lays out); the tool needs python 3.11, cc and clang, and reads only [docs/vfio/gsp-abi-615.md §1].

### Workflow for driver N

1. `gsp-abi.py snapshot --ogkm <tree-N> --out caraxes/abi/gsp-N/` at a clean commit, committed on its own [docs/vfio/gsp-abi-615.md §6 step 1].
2. `gsp-abi.py diff caraxes/abi/gsp-615.71.09 caraxes/abi/gsp-N --out caraxes/abi/delta-615.71.09-N.md`; exit 1 means a change to what the device implements [docs/vfio/gsp-abi-615.md §6 step 2].
3. Classify each change; any change in the stable layer is a baseline break and stops the workflow for a decision; redo the sender survey [docs/vfio/gsp-abi-615.md §6 step 3].
4. Regenerate the per-version tables into `src/ver/vN/` with `gsp-tables.py`, `ctrl-layouts.py` and `gsp-dtable.py`, after the version's `nvrm-sys` bindings exist; `ver/vN.rs` overrides what moved [docs/vfio/gsp-abi-615.md §6 step 4].
5. If the host moves to N, add a `hostabi.rs` row per changed host call, including GSS legacy sizes from an `nvidia-smi -q` trace [docs/vfio/gsp-abi-615.md §6 step 5].
6. Run `tools/check.sh`, the unit tests and the guest gates with a guest image of version N [docs/vfio/gsp-abi-615.md §6 step 6].
7. Record the delta; if N becomes the baseline, a decision row replaces D20 and the drift target moves [docs/vfio/gsp-abi-615.md §6 step 7].

- A baseline break is a size, offset or version-constant change in an `NV_ABI_STABLE` struct or enumerator, the element framing (`MCTP_MAGIC`, NVDM types 0x25/0x26, `queueElementHdrSize`, `maxRpcSize`, `MSGQ_VERSION_MAJOR` other than 2), the boot arguments, the GMCAPI header or an existing command or promoted key, or a change in the unstable-interface opt-in [docs/vfio/gsp-abi-615.md §7].

### The drift check

- `tools/check.sh` step `gsp-abi` (function `gsp_abi_baseline`) first runs `render --check` of the snapshot against `docs/vfio/gsp-abi-615-tables.md` [docs/vfio/gsp-abi-615.md §8].
- When a 615.71.09 tree is found (`$CARAXES_OGKM_615`, else the Leandro checkout beside the repository, else `/mnt/vmstore/caraxes/ogkm-615.71.09`) and cc and clang exist, it runs `diff --strict` of the snapshot against that tree; without a tree the drift half is skipped with a note [docs/vfio/gsp-abi-615.md §8].
- Against the Leandro checkout's tree the check found 0 driver-side and 0 device-side changes and the tables up to date [docs/vfio/gsp-abi-615.md §8; docs/vfio/README.md §Status 2026-09-25].

## Consequence for Leandro VFIO

- A new driver is a reviewed diff against `caraxes/abi/gsp-615.71.09/`, not a trace-driven bring-up; exit 1 of `diff` lists exactly the device code to touch.
- The stable layer (transport, boot arguments, GMCAPI, promoted keys) is written once; every control, alloc, RPC and event layout stays per version in the generated modules (D14).
- Host-side layouts (`hostabi.rs`) and flag words need a manual step, because the snapshot does not know which kernel-side controls the device calls on the host.
- The device's answer columns change with the crate, so the snapshot is regenerated after device work; that change never fails the drift check.
- RPC, event and class inventories behind these counts: see [gsp-rpc-events-classes.md](gsp-rpc-events-classes.md).

## Open

- The per-field view of the SM-order entry (`virtualDpcId`) needs the struct in `ctrl-layouts.py`; today the diff shows only its size change [docs/vfio/gsp-abi-615.md §5, §9].
- Controls compiled only into other build profiles (Windows) are not in the export tables and not in the snapshot [docs/vfio/gsp-abi-615.md §9].
- The categories A to E and the device provenance are `gsp-surface.py` heuristics; an improvement shows as a device-side change [docs/vfio/gsp-abi-615.md §9].
- The build default `DRIVER_VERSION` still says 610.57.04, so host tools that call `RmClient::new` panic on the 615 host until the pin moves [docs/vfio/cutover-615.md §Open points item 1].
