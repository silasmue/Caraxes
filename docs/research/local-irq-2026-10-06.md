# Experimental local IRQ ownership

The paired Caraxes and Cloud Hypervisor implementation moves the exact TU106
interrupt tree and MSI delivery into the VMM. Guest tree writes and explicit
rearm still exit to KVM, but complete locally without a VFIO-user socket RPC.
The backend publishes complete pending-bitset drains and controls through a
bounded, sequenced shared-memory queue. The cause queue is never guest mapped.

## Enablement

Both peers must opt in before a fresh boot:

- Backend: `CARAXES_LOCAL_IRQ=1`, TU106 host execution and boot model.
- Backend: `CARAXES_MSI_REARM_IOEVENTFD=0`.
- Display page: `CARAXES_DISPLAY_PAGE=exact-ro` or `0`.
- Paired CH user device: `x_caraxes_local_irq=required`.
- Keep the existing tree and selected FE mmap areas read-only in CH.

VERSION negotiation, PREPARE and COMMIT transfer ownership once. The VMM creates
its own read-only guest tree backing; the backend never receives that fd.
The shared cause queue is for cooperating host processes. Its mapping roles
prevent accidental writes; they are not a security boundary against a malicious
host peer that can remap its writable fd.

## Ordering and limits

- One VMM owner serializes queued folds, ACK/mask/trigger/rearm, controls and MSI.
- Separate backend drains retain duplicate-pending semantics across guest ACKs.
- CYA2 reads preserve raw config-mirror bytes through the ordinary backend read
  path; only rearm writes belong to the VMM. Reads do not replay an MSI.
- Unrelated socket RPCs publish causes before reply; CH drains after releasing
  its Client lock. The IRQ worker takes neither Client nor PCI device locks.
- Reset retires old producers before advancing the epoch. Late callbacks from
  the old generation cannot raise into the new tree.
- Queue full/corruption, peer loss and delivery/routing errors terminate the
  session. There is no per-access fallback or second tree owner.
- Initial scope: fresh x86_64 KVM, 4 KiB pages, one MSI vector. Snapshot,
  migration, restore and device hotplug/removal are unsupported.
- Trapped reads crossing the tree boundary and stores starting outside it but
  crossing into it terminate the session. In-page stores keep exact byte-lane
  and starting-dword behavior, including page-end stores.
- Disconnect requires a fresh backend and VMM process.

Headless GSP stall triggers now raise typed causes through `IntrShared`. This
repairs a separate legacy-tree source path; it is not a claim of equivalence
with that secondary tree's old interrupt enable behavior.

## Synchronous BAR shared transport

The optional BAR0 channel removes socket framing and per-request allocations.
It retains KVM exits for trapped accesses. The page is host-only; guests receive
no writable register or host GPU mapping.

- Backend: `CARAXES_BAR_SHMEM=1`, local IRQ ownership and idle poll `0`.
- Paired CH: `x_caraxes_bar_shmem=required,x_caraxes_local_irq=required`.
- Prepare after IRQ COMMIT, before exposing the device to the guest.
- One sealed 4 KiB page, two eventfds, nonce and monotonic sequence.
- Reads/writes of 1/2/4/8 bytes inside BAR0 use the shared slot. Other accesses
  select the socket before submission. Config, DMA and reset stay on the socket.
- The same Client lock and server thread serialize both transports. Existing
  register handlers and IRQ publication run before each shared reply.
- Timeout, peer loss, malformed slot or backend failure terminate the session.
  An accepted write is never retried through the socket.
- Experimental and default off. No asynchronous posted writes or batching.

The exact read-only FE publisher now stores only changed register words, while
keeping publication order, its fence, ACK semantics and full reset clearing.
Window-4 read-only mapping remains a separate hardware qualification candidate.

## Remaining write exits

- `ioeventfd` avoids a return from KVM to the VMM for matching writes. It does
  not eliminate the hardware VM exit or carry arbitrary values in a queue.
- Per-value eventfd counters lose order across registers and values. SET/CLEAR,
  ACK/host-cause and repeated rearm operations require that order. Existing
  doorbell token registration is not a replacement for the exact IRQ core.
- KVM coalesced MMIO preserves address, width and data in a bounded ring. It
  is a candidate only when delayed processing is valid and every dependent
  observation has an ordered drain, including ring-full fallback and reset.
- The current guest IRQ page is read-only memory. A read after a buffered ACK
  does not exit to drain writes. Keep IRQ updates synchronous until a complete
  visibility protocol is established. `irqfd` handles MSI injection;
  `resamplefd` does not implement NVIDIA ACK or CYA2 register semantics.
- Fully mapped pages can remove write exits where the existing hardware
  protocol supplies a completion handshake, such as the opt-in invalidation
  page. Validate completion, ordering and output before enabling that path.

References: [KVM ioeventfd](https://docs.kernel.org/virt/kvm/api.html#kvm-ioeventfd),
[coalesced MMIO](https://docs.kernel.org/virt/kvm/api.html#kvm-un-register-coalesced-mmio)
and [irqfd](https://docs.kernel.org/virt/kvm/api.html#kvm-irqfd).

## Next transport targets

Measure remaining BAR requests with the shared channel on and off in the same
binary pair. Then qualify the window-4 read-only page separately.

- `display/chan_page.rs` already has mapped PUT/GET kicks. Main currently couples
  them to the legacy FE mode. A selected-window implementation independent of
  exact FE is a candidate, subject to wraparound, reset and method-order tests.
- Keep ACK/enable/control synchronous until a queue preserves each write and
  dependent read visibility. A writable page plus polling loses repeated values.
- Coalesced MMIO avoids userspace exits, not hardware VM exits. Its queue must
  drain before dependent observations; current read-only IRQ reads do not exit.
- Posted shared writes need completion tickets for BAR2 flush, submission,
  side-effecting reads, DMA changes and reset. Never replay an accepted write.

device work and GPU execution; changing host load limits the comparison.

## Remaining backend work

In C205's render bracket, 31,766 writes to GSP queue head `0x110c00` account for
47.736 s of backend access time. Nested RM controls account for 41.101 s;
opaque PMGR `0x2080a613` alone accounts for 33.070 s, including 32.859 s in
host RM ioctls. These overlapping durations must not be added. Shared memory
does not remove the host operation.

- A612/A613 lack a public payload/side-effect contract in the available headers.
  Prior A613 captures change replies even for repeated identical requests.
  Do not invent a cache TTL or synthesize an answer from these observations.
- An ordered host-control worker could release the Device mutex during each
  real host ioctl, preserving request data, reply order, reset lifetime and
  failure semantics. It would reduce unrelated lock stalls, not the original
  caller's host latency. This remains a substantial separate change.
- The existing `CARAXES_RPC_IOEVENTFD` reconstructs each head write from the
  published ring and drains before trapped GSP observations. Qualify it
  separately; it reduces userspace exits without removing backend service.
- Legacy-covered display pages contribute 27,231 PUT writes and 17,557 reads
  in C205. Their PUT handlers total 1.291 s. A mapped PUT path still performs
  that command work and adds polling latency; it is a narrower target.

## Legacy kick lifecycle fixes

The old writable channel mapping remains coupled to legacy FE. It is not
enabled in C205/C206 or through a new independent option.

- The reactor acquires Device before sampling PUT and retains it through
  command consumption and GET publication. Posted work settles before sampling.
- Reset clears mapped state, sampled PUT/GET and watchdog ages. Per-channel
  generations discard samples/completions invalidated by reset or replacement.
- Display owns its channel page; publication no longer uses a process-global
  page shared by unrelated Device instances. Reset reattaches the same owner.
- Disconnect erases the retained writable image and terminates the backend.
  A new client needs a fresh backend/memfd.
- Actual Device/Server regressions cover socket reset and pushbuffer replacement
  while the reactor waits for Device, retained mappings, canonical/mapped ARMED
  output, GET completion and publication isolation between two Devices.

This repairs lifecycle bugs, not every legacy mapped-write assumption. Multiple
PUT stores still collapse into one observed value. Arbitrary stores on a writable
page, guest ordering before later controls, wrap/JUMP and notification chronology
need separate validation before an independent exact-mode mapped PUT option.
The idle legacy poll now takes Device even when no PUT changed; measure that
cost during a future Linux qualification. No hardware result uses this patch.
