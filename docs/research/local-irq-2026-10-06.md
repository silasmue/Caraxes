# Experimental local IRQ ownership

The paired Caraxes and Cloud Hypervisor implementation moves the exact TU106
interrupt tree and MSI delivery into the VMM. Guest tree writes and explicit
rearm still exit to KVM, but complete locally without a VFIO-user socket RPC.
The backend publishes complete pending-bitset drains and controls through a
bounded, sequenced shared-memory queue. The cause queue is never guest mapped.

## Enablement

Both peers must opt in before a fresh boot:

- Backend: `CARAXES_LOCAL_IRQ=1`, TU106 host execution and boot model.
- Backend: `CARAXES_MSI_REARM_IOEVENTFD=0`.
- Display page: `CARAXES_DISPLAY_PAGE=exact-ro` or `0`.
- Paired CH user device: `x_caraxes_local_irq=required`.
- Keep the existing tree and selected FE mmap areas read-only in CH.

VERSION negotiation, PREPARE and COMMIT transfer ownership once. The VMM creates
its own read-only guest tree backing; the backend never receives that fd.
The shared cause queue is for cooperating host processes. Its mapping roles
prevent accidental writes; they are not a security boundary against a malicious
host peer that can remap its writable fd.

## Ordering and limits

- One VMM owner serializes queued folds, ACK/mask/trigger/rearm, controls and MSI.
- Separate backend drains retain duplicate-pending semantics across guest ACKs.
- CYA2 reads preserve raw config-mirror bytes through the ordinary backend read
  path; only rearm writes belong to the VMM. Reads do not replay an MSI.
- Unrelated socket RPCs publish causes before reply; CH drains after releasing
  its Client lock. The IRQ worker takes neither Client nor PCI device locks.
- Reset retires old producers before advancing the epoch. Late callbacks from
  the old generation cannot raise into the new tree.
- Queue full/corruption, peer loss and delivery/routing errors terminate the
  session. There is no per-access fallback or second tree owner.
- Initial scope: fresh x86_64 KVM, 4 KiB pages, one MSI vector. Snapshot,
  migration, restore and device hotplug/removal are unsupported.
- Trapped reads crossing the tree boundary and stores starting outside it but
  crossing into it terminate the session. In-page stores keep exact byte-lane
  and starting-dword behavior, including page-end stores.
- Disconnect requires a fresh backend and VMM process.

Headless GSP stall triggers now raise typed causes through `IntrShared`. This
repairs a separate legacy-tree source path; it is not a claim of equivalence
with that secondary tree's old interrupt enable behavior.

Run the linked tests without a VM or GPU:

```sh
python3 tools/check-local-irq.py \
  --vmm /path/to/paired-cloud-hypervisor \
  --vmm-target /path/to/build-cache \
  --output /path/to/new-results
```

## Remaining write exits

- `ioeventfd` avoids a return from KVM to the VMM for matching writes. It does
  not eliminate the hardware VM exit or carry arbitrary values in a queue.
- Per-value eventfd counters lose order across registers and values. SET/CLEAR,
  ACK/host-cause and repeated rearm operations require that order. Existing
  doorbell token registration is not a replacement for the exact IRQ core.
- KVM coalesced MMIO preserves address, width and data in a bounded ring. It
  is a candidate only when delayed processing is valid and every dependent
  observation has an ordered drain, including ring-full fallback and reset.
- The current guest IRQ page is read-only memory. A read after a buffered ACK
  does not exit to drain writes. Keep IRQ updates synchronous until a complete
  visibility protocol is established. `irqfd` handles MSI injection;
  `resamplefd` does not implement NVIDIA ACK or CYA2 register semantics.
- Fully mapped pages can remove write exits where the existing hardware
  protocol supplies a completion handshake, such as the opt-in invalidation
  page. Validate completion, ordering and output before enabling that path.

References: [KVM ioeventfd](https://docs.kernel.org/virt/kvm/api.html#kvm-ioeventfd),
[coalesced MMIO](https://docs.kernel.org/virt/kvm/api.html#kvm-un-register-coalesced-mmio)
and [irqfd](https://docs.kernel.org/virt/kvm/api.html#kvm-irqfd).

## Next transport targets

Measure remaining ordinary BAR requests after qualification. A value-carrying
VMM-to-backend queue can remove synchronous write RPCs and per-value eventfd
limits, while retaining BAR2 flush, submission and reset ordering. Side-effecting
reads and DMA/reset controls still need explicit completion semantics. Shared
memory alone does not remove KVM exits or prove an FPS improvement.
