Reading: this guest kernel's DRM headers disagree with what 610.57.04's nvidia-drm source
(and its conftest.sh probes) expect for a 6.8-labelled kernel -- several DRM helper
signatures the source calls (colorspace property creators, aperture-conflict removal) do
not match, and conftest results that should gate alternate code paths
(NV_DRM_MODESET_LOCK_ALL_END_ARGUMENT_COUNT, the two NV_IS_EXPORT_SYMBOL_PRESENT_* macros)
were never defined, so the plain #if reads them as 0 under -Werror=undef. This is a genuine
source/kernel-header mismatch, not a fuse or an RPC problem, and it predates any display RPC
question. No source in vendor/open-gpu-kernel-modules was touched to work around it (kickoff
rule 2: no guest driver patches without an operator-approved, documented temporary aid); the
mismatch is recorded here as a fact for whoever picks up D1/route E.

== Load: sudo insmod nvidia-modeset.ko ==
Attempt 1: FAILED.
  dmesg: nvidia_modeset: Unknown symbol acpi_video_register_backlight (err -2)
         nvidia_modeset: Unknown symbol __acpi_video_get_backlight_type (err -2)

Ubuntu kernel module, no relation to the NVIDIA driver) was not loaded, so the two
