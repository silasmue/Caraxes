# Commands of the sysmem-iova measurement, 2026-09-23 (Europe/Berlin)

Build (uid 1000):
  rustc -O --edition 2021 caraxes/tools/sysmem-iova.rs -o target/sysmem-iova

Run as root (the only commands that ran with sudo):
  14:30:13-14:30:20  sudo -n target/sysmem-iova measure --go --sizes 256 --reps 3 --pair   -> run1-256m.txt
  14:30:56-14:31:25  sudo -n target/sysmem-iova measure --go --sizes 1024 --reps 3         -> run2-1g.txt

Both runs used the first build of the tool, which always read every 4 KiB page
(the same as `--full-scan` in the current source; the 2 MiB default step was added
afterwards, see host-after.txt for why).

Inside each root process the tool switched to uid/gid 1000 before opening any device
(PR_SET_KEEPCAPS, setgroups(0), setresgid, setresuid), kept CAP_SYS_ADMIN only in the
permitted set with an empty effective set, and raised it into the effective set only
around NV0041_CTRL_CMD_GET_SURFACE_PHYS_ATTR ioctls (17 windows in run 1, 16 in run 2;
the first line of each run file shows the resulting capability sets). The RM client,
device, REGISTER_FD, RM_ALLOC_MEMORY (class 0x71), RM_FREE and the buffers ran as uid 1000.
Each run also sent GET_SURFACE_PHYS_ATTR once without the capability: 0x1b
NV_ERR_INSUFFICIENT_PERMISSIONS.

Read-only host inspection (uid 1000): /proc/meminfo, /proc/vmstat, /proc/cmdline,
/sys/kernel/iommu_groups/28/{type,devices,reserved_regions},
/sys/class/iommu/ivhd0/amd-iommu/features, journalctl -k, nvidia-smi --query-gpu.

What touched the host card: RM API calls of the two runs only (client, device,
OS-descriptor registrations of host system memory, the PHYS_ATTR queries, frees). No VRAM
allocation, no register access, no mapping, no module load, no unbind.
